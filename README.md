# Система бронирования конференц-залов Головного офиса

**Backend:** Java 17 + Spring Boot 3.3 + Maven. **Frontend:** React 18 + Vite. **Тестовый Outlook** и **тестовая почта:** Node.js (эмуляторы Microsoft Graph и SMTP-сервера).

## Запуск

Windows: двойной клик по `start-all.bat` (backend :8080 и frontend :5173). При необходимости: `start-mock-outlook.bat` (:9000) и `start-mock-mail.bat` (SMTP :2525, веб :8025).
Вручную:
```
cd backend  && mvn spring-boot:run
cd frontend && npm install && npm run dev
cd mock-outlook && node server.js
cd mock-mail && node server.js
```
Открыть: http://localhost:5173. Тесты: `cd backend && mvn test`.

База (H2-файл `backend/data/`) обновляется сама: новые таблицы и колонки добавляются при запуске.
Чтобы начать с чистой базы, остановите backend и удалите `backend/data/`.

## Вход
- Сотрудник: email и пароль. Демо: `ivanov@company.ru` / `Employee123` (только при `app.seed-demo-data: true`).
- Администратор: `admin` / `admin123` (меняется через `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `JWT_SECRET`).

## Участники брони
При создании брони (шаг 3) организатор выбирает коллег из списка (поиск по ФИО и email).
- Организатор и участники видят бронь в «Мои бронирования» (приглашённые помечены «Приглашён»).
- Изменять и отменять бронь может только организатор и администратор; состав участников меняется в «Изменить».
- Организатор + участники не могут превышать вместимость зала (проверка на сервере и в интерфейсе).
- Отключённого сотрудника добавить нельзя; дубли и сам организатор в списке игнорируются.
- Приглашённым отправляется письмо (см. раздел «Почтовые уведомления»).

## Почтовые уведомления
Письма отправляются фоновым потоком после успешного сохранения брони. Сбой почты не мешает бронированию, результат каждой отправки записывается в «Журнал».

| Событие | Кто получает письмо |
|---|---|
| Сотрудника добавили участником | приглашённый (с вложением `meeting.ics`) |
| Изменились зал, дата или время | все участники |
| Сотрудника убрали из участников | исключённый |
| Встреча отменена | все участники |
| Бронь изменил или отменил администратор | дополнительно организатор |

Отключённым сотрудникам письма не отправляются. Вложение `.ics` добавляет событие в календарь (Outlook, Google, Apple), но это не «приглашение на встречу» с ответами: настоящее событие в календаре Outlook создаёт интеграция через Graph (следующий этап).

**Включение:** переменные окружения backend (по умолчанию почта выключена).

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `MAIL_ENABLED` | `false` | включить отправку |
| `MAIL_HOST`, `MAIL_PORT` | `localhost`, `2525` | SMTP-сервер |
| `MAIL_USERNAME`, `MAIL_PASSWORD` | пусто | логин и пароль SMTP |
| `MAIL_AUTH`, `MAIL_STARTTLS` | `false` | включите `true`, если сервер требует вход / STARTTLS |
| `MAIL_FROM`, `MAIL_FROM_NAME` | `booking@company.test`, `Бронирование залов` | отправитель |
| `SITE_URL` | `http://localhost:5173` | адрес сайта для ссылки в письме |

Проверка настроек: Администратор, вкладка «Почта», кнопка «Отправить тестовое письмо» (покажет ошибку подключения).

### Тестовая почта
`mock-mail` принимает письма как SMTP-сервер и показывает их на странице, наружу ничего не отправляется.
1. `node server.js` в папке `mock-mail`, открыть http://localhost:8025.
2. Запустить backend с `MAIL_ENABLED=true` (остальное по умолчанию уже указывает на :2525).
3. Создать бронь с участниками: письма появятся на http://localhost:8025 (HTML, текст, вложение `.ics`).

### Реальный сервер (пример для Microsoft 365)
`MAIL_HOST=smtp.office365.com`, `MAIL_PORT=587`, `MAIL_AUTH=true`, `MAIL_STARTTLS=true`, `MAIL_USERNAME` и `MAIL_PASSWORD` почтового ящика, `MAIL_FROM` равен этому ящику.
Для корпоративного Exchange параметры уточните у ИТ-отдела. Пароль храните только в переменных окружения.

## Сотрудники
Админ → «Сотрудники»:
1. **Импорт из CSV** (`ФИО; email; телефон`, UTF-8 или windows-1251): создаёт учётные записи с временными паролями (показываются один раз, скачиваются файлом). При первом входе сотрудник обязан сменить пароль.
2. **Синхронизация с Outlook** (Microsoft Graph): создаёт, обновляет и отключает сотрудников по каталогу. Включается `GRAPH_ENABLED=true`.
3. Ручное добавление, изменение, сброс пароля, отключение.

## Тестовый Outlook
`mock-outlook` эмулирует Microsoft Graph: получение токена, `GET /v1.0/users` (с `$select`, `$top`, страницами), события календаря.
1. `node server.js`, открыть http://localhost:9000.
2. Загрузить `mock-outlook/employees-50.csv` (50 вымышленных сотрудников, домен `company.test`).
3. Включить в backend `GRAPH_ENABLED=true` (настройки по умолчанию уже указывают на эмулятор) и перезапустить.
4. На сайте: Администратор → Сотрудники → «Синхронизировать с Outlook».

Правила синхронизации: сотрудник связывается с записью каталога по её идентификатору (или по email); ФИО, email и телефон берутся из каталога; отключён или удалён в каталоге — отключается на сайте; пустой ответ каталога отменяет синхронизацию; записи без email или с чужим доменом пропускаются.

Для настоящего Outlook замените в `application.yml` (или переменных окружения):
`GRAPH_BASE_URL=https://graph.microsoft.com/v1.0`, `GRAPH_AUTHORITY=https://login.microsoftonline.com`, `GRAPH_TENANT_ID`, `GRAPH_CLIENT_ID`, `GRAPH_CLIENT_SECRET`
(приложение в Microsoft Entra ID с разрешением `User.Read.All`, тип Application, с согласием администратора). Задайте `CORPORATE_EMAIL_DOMAIN`.

## Допущения
- Рабочие часы 08:00–20:00, шаг 30 минут (`app.work-day-*`).
- Сотрудник не может создавать и менять брони в прошлом.
- Отмена «мягкая» (статус `CANCELLED`). Зал с бронями удалить нельзя, только деактивировать.
- Контакты организатора и список участников видны всем вошедшим сотрудникам.
- PostgreSQL: `--spring.profiles.active=postgres`.
